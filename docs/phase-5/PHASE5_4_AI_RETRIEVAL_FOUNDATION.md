# Phase 5.4 — AI Retrieval Foundation

## 1. Objective

Phase 5.4 establishes the first governed retrieval boundary for AI consumers.

The objective is to expose trusted structured facts for future LLM and product consumers without introducing unnecessary semantic infrastructure.

The phase deliberately starts with:

```text
structured retrieval
```

and does not yet introduce:

```text
embeddings
vector database
Bedrock Knowledge Bases
semantic search
LLM generation
```

---

## 2. Architectural Principle

Structured quantitative facts must remain structured.

The AI layer must not use semantic retrieval to recover exact market facts such as:

```text
ticker
price
return
volume
ML features
business date
```

The platform therefore separates:

```text
Structured facts
    |
    +--> structured retrieval

Documents / semantic context
    |
    +--> future RAG
          |
          +--> embeddings
          |
          +--> vector store
```

---

## 3. AI Retrieval Boundary

The structured AI context is built from two governed serving sources:

```text
Daily Consumption Layer
        +
ML Serving Foundation
        |
        v
AI Structured Context
```

The AI layer does not consume RAW or SILVER directly.

---

## 4. Source Contracts

Daily source:

```text
data/serving/daily/latest_snapshot.json
```

ML source:

```text
data/serving/ml/latest_inference_features.json
```

Both manifests must be:

```text
status = READY
```

---

## 5. Temporal Reconciliation

The AI context requires both serving layers to represent the same business state.

Required invariant:

```text
Daily trade_date
=
ML feature_date
```

Validated:

```text
2026-08-28
=
2026-08-28
```

If the dates diverge, the structured retrieval build fails closed.

---

## 6. Entity Alignment

The AI context is produced at one record per ticker.

Required invariant:

```text
Daily Snapshot tickers
=
ML Serving tickers
```

Validated state:

```text
Daily tickers = 267
ML tickers    = 267
AI tickers    = 267
```

Duplicate or missing ticker identities are rejected.

## 13. Provenance Section


---

## 14. No Generated Text

Phase 5.4 does not generate natural-language descriptions.

The context contains only governed structured facts.

Explicitly absent:

```text
prompt
completion
answer
LLM-generated summary
LLM-generated recommendation
```

Natural-language interpretation belongs to a later AI generation layer.

---

## 15. Exact Structured Retrieval

The initial retrieval mechanism is:

```text
retrieve_by_ticker(ticker)
```

Example:

```text
retrieve_by_ticker("GGRC11")
```

This performs exact structured lookup.

It does not use:

```text
vector similarity
embedding search
semantic ranking
LLM reasoning
```

## 20. S3 Idempotency

The first execution created:

```text
serving/ai/fii_structured_context.jsonl
serving/ai/fii_structured_context.json
```

The second consecutive execution validated idempotency.

Context:

```text
physical SHA identical
logical SHA identical
-> upload skipped
```

Manifest:

```text
physical SHA different
logical SHA identical
-> repackaging detected
-> upload skipped
```

No unnecessary S3 versions are created when the business state remains unchanged.

## 25. Why No Vector Database Yet

Vector databases are designed for semantic similarity retrieval.

The current structured context contains exact governed facts.

Examples:

```text
"What is GGRC11 close_price?"
"What is the latest return_20d?"
"What is the ticker's CVM status?"
```

These questions are better served through exact structured retrieval.

A vector database would add:

```text
cost
indexing
synchronization
operational complexity
semantic approximation
```

without improving exact structured lookup.

---

## 26. Future Semantic Retrieval

Vector retrieval remains planned for content that benefits from semantic search, such as:

```text
management reports
fund documents
market commentary
regulatory disclosures
long-form text
```

This responsibility belongs to Phase 5.5.

## 27. Future LLM Consumption

A future LLM flow can use structured context as:

```text
User Question
      |
      v
Retrieval Router
      |
      v
Structured Retriever
      |
      v
Governed ticker context
      |
      v
LLM
      |
      v
Natural-language interpretation
```

The LLM does not become the source of quantitative truth.

---

## 28. Hybrid Future Architecture

The target future architecture is:

```text
User Question
     |
     v
Retrieval Router
     |
     +--------------------------+
     |                          |
     v                          v
Structured Retrieval      Semantic Retrieval
     |                          |
     v                          v
Exact governed facts       Documents / chunks
     |                          |
     +-------------+------------+
                   |
                   v
                LLM Context
                   |
                   v
                  LLM
```

This preserves exact quantitative retrieval while allowing future semantic context.
